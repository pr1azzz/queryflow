# ПР6 — шпаргалка по 25 пунктам таблицы оценивания

Источник: §7.6, страницы 55–56 «ПР6_Django_Shablony_кор.pdf».
Всего 25 показателей, 1,25 балла. Примеры Roomly адаптированы к QueryFlow:
помещение → вопрос, бронирование → ответ, статус → состояние вопроса.

На этапе ПР6 данные берутся из JSON и объектов ПР3. После ПР7 источником
станет SQLite, но наследование, блоки, include, static и URL останутся теми же.
Для демонстрации именно JSON-версии использовать коммит `c921528` (`PR6:`).
В текущем коде ПР7 `question` — строка SQLite: вместо `question.author.name`
используется `question.author_name`, вместо `question.category.name` —
`question.category_name`. Поиск во view выполняется `fetch_one()`, а не
`get_question_by_id()`. Остальные описанные приёмы шаблонов сохранились.
Все учебные изменения ниже временные: после демонстрации вернуть исходный код.

## 1. Наследование шаблонов

**Показать:** `templates/base.html` и
`questions/templates/questions/question_list.html`.
`{% extends 'base.html' %}` выбирает родительский каркас. Дочерний шаблон
переопределяет его блоки. В текущей версии ПР7 внутри `block title`
стоит `{{ heading|default:"Вопросы" }}`. Значение `heading` приходит из
`questions/views.py`, а `default` — запасной текст, который используется,
только если `heading` отсутствует или имеет ложное значение. Поэтому замена
одного слова «Вопросы» внутри `default` не изменит название вкладки.

Для демонстрации временно заменить **весь блок** в `question_list.html`:

```django
{% block title %}Обсуждения{% endblock %}
```

Сохранить файл и обновить `/questions/`: название вкладки станет
«Обсуждения | QueryFlow», общее меню останется прежним. Это название
вкладки браузера, а не крупный заголовок внутри страницы.
Изменение текста внутри `block title` самого `base.html` здесь тоже не
видно: дочерний шаблон переопределяет этот блок.
`extends` должен быть первым шаблонным тегом дочернего файла.

## 2. Переопределение блоков

В `base.html` есть `title` и `content`. В дочернем шаблоне блоки с теми же
именами заменяют соответствующие части родителя. В файле
`questions/templates/questions/question_list.html` временно заменить
**всю строку** `<h1>{{ heading|default:'Вопросы' }}</h1>` на:

```html
<h1>Обсуждения сообщества</h1>
```

Сохранить файл и обновить `/questions/`. Это меняет видимый заголовок;
`block title` меняет название вкладки. Здесь также недостаточно поменять
только текст внутри `default`, поскольку `heading` уже задан во view.
Изменение вне блоков наследуемого шаблона не является способом добавить
содержимое страницы.

Если нужно изменить одновременно вкладку и `<h1>` без замены выражений
в шаблоне, в функции `questions()` файла `questions/views.py` изменить
`"heading": "Вопросы"` на `"heading": "Обсуждения"`. Для маршрутов
`/questions/open/` и `/questions/unanswered/` заголовки задаются отдельно.
После демонстрации вернуть исходные строки.

## 3. Передача контекста

В `questions/views.py`: `render(request, 'questions/question_list.html',
{'cards': cards})`. Контекст — словарь, ключи становятся именами переменных.
В шаблоне `{% for item in cards %}` читает этот ключ. Если назвать его
`items`, но оставить `cards` в шаблоне, список перестанет выводиться и
сработает `empty`. Исправление — согласовать имена в обоих местах.

## 4. Атрибуты объектов

В `question_detail.html`: `{{ question.text }}`, `{{ question.id }}`.
На этапе ПР6 `question` — объект `Question`, у него есть `category` и `author`:
`{{ question.author.name }}`. Точка в DTL позволяет обращаться к ключам
словаря, атрибутам и индексам. `{{ question.unknown_field }}` обычно
выведет пустую строку: это не аналог прямого Python-доступа с AttributeError.

## 5. Отсутствующая переменная

Временно добавить `{{ missing_value }}` в `question_detail.html`.
При стандартном `string_if_invalid=''` Django ничего не выведет.
Отсутствие ошибки затрудняет диагностику: нужно сверять контекст, имя
переменной и её атрибуты. Это правило не гарантирует молчания любого тега:
например, неверный аргумент `{% url %}` может вызвать `NoReverseMatch`.

## 6. Автоматическое экранирование

В `question_detail.html` текст выводится через `{{ question.text }}`.
Строка `<script>alert(1)</script>` отображается как текст, поскольку
`<` и `>` экранируются. Не добавлять `safe` или `autoescape off` к
пользовательским данным: иначе возможен XSS. Проверка без изменения данных:
`python -m pytest tests/test_templates.py -k autoescaped -v`.

## 7. Коллекции и пустые результаты

В `question_list.html` есть `{% for item in cards %}…{% empty %}…{% endfor %}`.
Временно передать `{'cards': []}`: появится «Вопросов пока нет».
Пустой список — нормальный результат, а не ошибка сервера.
В списках категорий и ответов предусмотрены аналогичные ветви.

## 8. Условное отображение

Открыть `questions/templates/questions/includes/question_status.html`.
`if question.is_closed` показывает «закрыт»; `elif answers_count` —
«открыт»; `else` — «ожидает ответа». На ПР6 изменить `is_closed` в JSON,
обновить страницу и вернуть исходное значение. При ПР7 менять запись SQLite.
Закрытый вопрос имеет приоритет независимо от числа ответов.

## 9. Фильтры

Используются `cards|length`, `question.text|default:'Без текста'|truncatechars:150`.
`length` считает элементы, `truncatechars` сокращает длинный текст,
`default` подставляет запасное значение. Добавить временно `|upper`
к названию категории: изменится только отображение, не данные хранилища.

## 10. Пустое значение и default

В `categories/category_list.html`: `category.name|default:'Без названия'`.
Передать пустое имя — появится подпись. `default` применяется к ложным
значениям, включая `''`, `None`, `0`, `False`, а не только к отсутствующим.
Для замены только `None` предназначен `default_if_none`.
Проверять на временном контексте, не сохранять некорректные данные в базе.

## 11. Повторное использование include

`base.html` включает `includes/navigation.html`. Список вопросов включает
`questions/includes/question_card.html`; карточка и страница вопроса —
`question_status.html`. Изменить подпись меню во включаемом шаблоне:
она обновится на всех страницах. `include` вставляет фрагмент,
`extends` организует наследование каркаса — это разные задачи.

## 12. Контекст включаемого шаблона

В `question_list.html` используется:

```django
{% include 'questions/includes/question_card.html' with question=item.question answers_count=item.answers_count only %}
```

`with` задаёт имена, `only` ограничивает контекст переданными переменными.
Если передать `entry=item.question`, но внутри оставить `question`,
данные потеряются; тег URL с отсутствующим ID может дать `NoReverseMatch`.
Исправить имя аргумента или обращения во фрагменте согласованно.

## 13. Динамические URL

В карточке: `{% url 'questions:detail' question.id %}`.
Для ID 1 получится `/questions/1/`. Временно заменить аргумент на `2`:
адрес ссылки изменится на `/questions/2/`. Тег строит адрес по маршруту,
но не проверяет существование записи. ID 999 даст ссылку, переход — 404.

## 14. Пространства имён

В `questions/urls.py`: `app_name = 'questions'`, у маршрута — `name='detail'`.
Полное имя — `questions:detail`; у ответа есть своё `answers:detail`.
Если переименовать namespace или name, обновить все `{% url %}`, `reverse()`
и проверки этих имён. Иначе возникнет `NoReverseMatch`. Сами пути могут
оставаться прежними: имя маршрута и текст URL — разные вещи.

## 15. Конвертер маршрута

`path('<int:question_id>/', views.question_detail, name='detail')`
преобразует цифры в Python `int`. `/questions/abc/` не соответствует
конвертеру: view не вызывается. `/questions/999/` соответствует, но
объект может отсутствовать. Конвертер проверяет форму параметра, не данные.

## 16. Отсутствующий объект

В ПР6 `question_detail()` получает объект через `get_question_by_id()`.
Если результат `None`, возвращает `render(request, '404.html',
{'message': 'Вопрос не найден'}, status=404)`.
Открыть `/questions/999/`, проверить Network → Status Code: 404.
Без проверки обращение к полям `None` может привести к ошибке 500.

## 17. Маршрут и ресурс

`/nonexistent/`: маршрута нет, Django обращается к общему `handler404`
при `DEBUG=False`. `/questions/999/`: маршрут найден, но представление
не нашло запись и само вернуло 404. Явный ответ `status=404` не вызывает
`handler404` повторно. При `DEBUG=True` неизвестный маршрут показывает
техническую страницу; ответ отсутствующего объекта остаётся нашим.

## 18. Ошибка поиска шаблона

В `render()` имя файла должно совпадать с реальным относительным путём.
`questions/wrong.html` даст `TemplateDoesNotExist`. Файл найден, но тег
неправильный — `TemplateSyntaxError`. При диагностике проверить `DIRS`,
`APP_DIRS`, `INSTALLED_APPS` и путь `questions/templates/questions/...`.
Это обычно ошибки 500, а не «страница не найдена» с кодом 404.

## 19. Синтаксис шаблона

У `{% for %}` должен быть `{% endfor %}`, у `{% if %}` — `{% endif %}`,
у блока — `{% endblock %}`. Удаление закрывающего тега в `question_list.html`
приведёт к `TemplateSyntaxError`. Восстановить тег, проверить вложенность
и обновить страницу. Команда `check` не заменяет открытие всех шаблонов.

## 20. Статические ресурсы

В `base.html`: `{% load static %}` и
`{% static 'homepage/css/style.css' %}`, аналогично JS и SVG-логотипу.
Файлы лежат в `homepage/static/homepage/`. Неверный путь обычно даёт
404 именно на запрос ресурса, при этом HTML может иметь 200.
Проверить Network и `python manage.py findstatic homepage/css/style.css`.
При `DEBUG=False` для локальной демонстрации статики использовать
`runserver --insecure`; это не настройка рабочего сервера.

## 21. CSS и классы

В `homepage/static/homepage/css/style.css` есть `.question-card`.
В карточке указан `class='card question-card mb-3'`.
Временно изменить `border-color` или `box-shadow` правила, обновить страницу.
Селектор с точкой выбирает элементы по классу. Если изменений нет,
проверить загрузку CSS, кэш и перебивающее правило в Computed Styles.

## 22. JavaScript

`base.html` подключает `homepage/js/main.js` с `defer`. Скрипт находит
`#current-year` и устанавливает текущий год. `defer` позволяет дождаться
разбора HTML. Если файл не загрузился — ошибка Network/404; если загрузился,
но код неверен — смотреть Console. Несовпадение ID может не дать ошибки:
в коде стоит `if (yearElement)`, поэтому запись просто не выполнится.

## 23. Организация каталогов

Общий каркас — `templates/base.html`; шаблон вопросов —
`questions/templates/questions/question_list.html`; ответов —
`answers/templates/answers/answer_list.html`.
В `render()` используется `'questions/question_list.html'` без первой
папки `templates`. `DIRS=[BASE_DIR / 'templates']` добавляет общие файлы,
`APP_DIRS=True` — поиск в зарегистрированных приложениях.
Вложенный namespace предотвращает конфликт одинаковых имён файлов.

## 24. Согласованность view и шаблона

В `question_detail()` ключ `'question'` соответствует `{{ question.text }}`.
Изменить ключ на `'item'`, но оставить шаблон — текст исчезнет,
а URL с недоступным ID может вызвать `NoReverseMatch`. Вернуть имя
или обновить все ссылки. Проверять всю цепочку: найденный объект →
словарь контекста → переменная → атрибут → HTML.

## 25. Полный путь запроса

`GET /questions/1/` → `queryflow/urls.py` и `include('questions.urls')` →
`<int:question_id>/` → `question_detail(request, question_id=1)` →
загрузка и поиск объекта → контекст → `question_detail.html` →
`base.html` и включаемые фрагменты → HTML-ответ 200.
Если ID отсутствует, 404 формируется во view до основного шаблона.
Если ID текстовый, ошибка возникает раньше — при разрешении маршрута.
