# QueryFlow — Система учета вопросов и ответов

## Назначение

QueryFlow — учебное приложение для учета вопросов и ответов пользователей.
Система помогает публиковать вопросы по категориям, добавлять ответы и
отслеживать статус обсуждения (открыт / закрыт / без ответа).

## Целевая аудитория

- студенты и преподаватели, которым нужен простой учёт Q&A;
- участники учебных проектов и внутренних FAQ-сервисов;
- администраторы, контролирующие категории и статусы вопросов.

## Предметная область

Предметная область — учёт вопросов и ответов. Пользователи задают вопросы,
относят их к категориям и получают ответы. В дальнейшем приложение будет
расширено до веб-сервиса на Django с базой данных, авторизацией и API.

## Основные сущности

- **Пользователь (User)** — автор вопроса или ответа (имя, роль).
- **Вопрос (Question)** — текст вопроса, категория, статус, автор.
- **Ответ (Answer)** — текст ответа, связь с вопросом, автор.
- **Категория (Category)** — тематическая группа вопросов (название, активность).

## Основные функции

- проверка возможности публикации вопроса (длина текста, активность категории);
- определение статуса вопроса (открыт / закрыт / ожидает ответа);
- формирование краткой карточки вопроса для вывода в консоль;
- (план) создание и просмотр ответов;
- (план) CRUD по сущностям, роли пользователей, веб-интерфейс и API.

## План развития

На следующих этапах дисциплины планируется:

- ПР2 — консольная программа с несколькими сценариями, коллекциями и модулями;
- ПР3 — реализация сущностей в виде классов (ООП);
- ПР5–ПР7 — Django-проект, шаблоны, модели и база данных;
- ПР9–ПР11 — ORM, формы, регистрация и авторизация пользователей;
- разработка REST API;
- контейнеризация приложения (Docker);
- настройка CI/CD;
- автоматизированное тестирование (pytest).
