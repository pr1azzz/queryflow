# ПР9 — шпаргалка по 30 пунктам таблицы оценивания

Источник: §7.3, страницы 70–74 PDF ПР9.

Все примеры относятся к QueryFlow. Номера ниже соответствуют строкам таблицы оценивания, а не разделу «Контрольные вопросы».
Команды запускайте из корня проекта с активированным `.venv`. Адрес сайта: `http://127.0.0.1:8000/` при обычном `python manage.py runserver`.
Если сервер запущен на другом порту, используйте его адрес. Сохраняйте файл после изменения и обновляйте нужную страницу.
Учебные изменения кода возвращайте после демонстрации; для CRUD создавайте отдельные тестовые записи.
Участник `participants.User` — автор вопросов и ответов; учётная запись Django Admin — отдельная модель авторизации.

Для примеров ORM откройте `python manage.py shell` и выполните:

```python
from categories.models import Category
from participants.models import User
from questions.models import Question
from answers.models import Answer
from django.db.models import Count, F, Q
```

Контрольная точка ПР9: `ca17483`. Ниже примеры для текущего проекта ПР11; замена is_closed на status и переход на Form отмечены в соответствующих пунктах.

## 1. Описание модели и параметры полей

Откройте `questions/models.py`: TextField — текст, DateField — дата, ForeignKey — связи. `blank` управляет проверкой пустого значения, `null` — хранением NULL, `default` — начальным значением. Для демонстрации измените `verbose_name` поля, выполните `makemigrations`, посмотрите AlterField. Верните параметр и создайте обратную миграцию; не удаляйте уже применённые миграции вручную.

## 2. ForeignKey и on_delete

`Question.category` и `Question.author` используют `PROTECT`. В shell: `q = Question.objects.first(); q.category; q.author`. Удаление используемой категории вызовет ProtectedError. CASCADE удалил бы зависимые записи, SET_NULL требует null=True. Для показа удаления создайте отдельную категорию без вопросов.

## 3. Прямые и обратные связи

`q.category` возвращает категорию, `q.category.questions.all()` — её вопросы; `q.answers.all()` — ответы. Обратные имена заданы через related_name. `q.category_id` — число без дополнительного запроса, `q.category` — объект. Если изменить related_name, нужно согласовать запросы и создать миграцию.

## 4. Создание и применение миграций

Покажите `questions/migrations/0001_initial.py`. Команды: `python manage.py makemigrations`, `python manage.py migrate`, `python manage.py showmigrations`. Первая создаёт описание изменений, вторая применяет их к БД; отметка [X] означает применение. Для проверки согласованности используйте `makemigrations --check`.

## 5. Создание объекта

В shell: `c = Category(name="Проверка ПР9"); c.name = "Тестовая категория"; c.save(); Category.objects.get(pk=c.pk).name`. Сохранится последнее присвоенное значение. При `Category.objects.create(...)` создание и сохранение происходят вместе. После демонстрации удалите только эту тестовую категорию: `c.delete()`.

## 6. Изменение и save

Создайте тестовую категорию: `c = Category.objects.create(name="До")`. Затем `c.name = "После"`: в БД ещё «До». После `c.save(update_fields=["name"])` повторный get покажет «После». `refresh_from_db()` заменяет состояние объекта значениями БД. В конце `c.delete()`.

## 7. Удаление объекта

`c = Category.objects.create(name="Удалить только этот тест"); pk = c.pk; c.delete(); Category.objects.filter(pk=pk).exists()` даст False. Сравните с `Category.objects.filter(pk=pk).delete()` — удалением выборки. Не удаляйте рабочие категории: PROTECT защищает связанные вопросы. Готовая безопасная демонстрация CRUD: `python manage.py orm_demo`.

## 8. QuerySet и filter

`Question.objects.all()` — набор вопросов, `Question.objects.filter(status=Question.Status.OPEN)` — открытые. Измените OPEN на CLOSED и сравните ID. QuerySet ленивый: составление запроса обычно не обращается к БД, а list(), перебор и вывод результата приводят к выполнению.

## 9. Фильтрация по связанному полю

`Question.objects.filter(category__name__icontains="Python")` ищет по названию категории через JOIN. Замените `category__name` на `author__name` и поисковое слово на имя автора. `category_id=1` проверяет внешний ключ без поиска по названию. Код: `questions/queries.py`, filtered_questions().

## 10. Несколько условий

На `/questions/` выберите категорию, автора и начальную дату. Эти условия в filtered_questions() объединяются через AND: запись должна удовлетворять всем. Для OR используется Q: `Q(category__name__icontains="Python") | Q(author__name__icontains="Иван")`. Снимите один фильтр и сравните число найденных записей.

## 11. Проверка пользовательского ввода

В текущей версии после ПР11 откройте `QuestionFilterForm` в `questions/forms.py` и list_response() в views.py: request.GET → is_valid() → cleaned_data. Попробуйте `?date=wrong` или `?category=abc`: получите 400 и ошибки формы. В контрольном коммите ПР9 эту проверку выполняет `questions/parameters.py`.

## 12. Сортировка

`Question.objects.order_by("created_on", "pk")` — сначала старые; с минусом — новые. Дополнительный pk обеспечивает устойчивый порядок при одинаковой дате. На `/questions/` выберите разные варианты порядка. Сортировка по связанной категории задаётся `category__name`.

## 13. Сортировка по GET-параметру

Покажите `SORTS` в `questions/queries.py`: разрешённые ключи newest, oldest, category, author. `?sort=oldest` меняет порядок, `?sort=unknown` даёт ошибку 400. Произвольный ввод не передаётся в order_by(): это исключает неожиданные поля и ошибки FieldError.

## 14. values и отдельные поля

`Question.objects.values("id", "text", "category__name")` возвращает словари, а не объекты моделей. Добавьте `"author__name"` и сравните ключи. Рабочий пример — question_rows() в `questions/queries.py`: шаблон карточки использует именно возвращённые ключи.

## 15. annotate и F

`Question.objects.annotate(category_name=F("category__name")).values("id", "category_name")`. F обращается к полю SQL-запроса, annotate добавляет именованное выражение. В question_rows() также создаётся author_name. Это данные связанной таблицы, не новая сохранённая колонка модели.

## 16. Отсутствующий объект и 404

Откройте question_detail() в `questions/views.py`: get_object_or_404(). Сравните `/questions/1/` и `/questions/999999/`. Для отсутствующего ID сервер возвращает 404. При DEBUG=True видна техническая страница, при DEBUG=False — наш `404.html`; статус остаётся 404.

## 17. Агрегаты и условия Q

На `/questions/statistics/` покажите общее количество и три статуса. В statistics_context(): aggregate(total=Count("pk"), open_count=Count("pk", filter=Q(status=Question.Status.OPEN))). Count с условием считает только подходящие строки. На этапе ПР9 условие использовало is_closed; ПР10 заменило его статусом.

## 18. Групповая статистика

`Category.objects.annotate(questions_count=Count("questions")).order_by("-questions_count", "pk")` считает вопросы каждой категории. На странице статистики задайте минимум 0 и 1. Фильтрация по questions_count после annotate становится отбором групп; нулевые категории видны при минимуме 0.

## 19. select_related

В question_detail() загружаются category и author через select_related(). Откройте SQL в Django Debug Toolbar на `/questions/1/`: в запросе есть JOIN. Обращение к q.category.name и q.author.name после такой загрузки не вызывает отдельных запросов. Проверка: тест `test_values_and_select_related_use_one_query`.

## 20. Только нужные данные без лишних запросов

Откройте question_rows(): annotate(F(...), Count(...)).values(...). В Toolbar на `/questions/` найдите запрос карточек. Имена автора и категории уже выбраны в SQL; для словарей values() дополнительный select_related() не нужен. Не путайте этот запрос с отдельными запросами вариантов фильтра и подсчётом Paginator.

## 21. Передача контекста

В list_response() результат страницы преобразуется в `cards`; в question_list.html выполняется `{% for item in cards %}`. Временно замените имя cards в цикле на отсутствующее demo_cards: сработает empty. Верните имя. Имена ключей словаря контекста и переменных шаблона должны совпадать.

## 22. Размер страницы

В `questions/views.py` временно замените PAGE_SIZE = 10 на 1. Откройте список с двумя вопросами: появится несколько страниц. Paginator получает QuerySet и размер страницы, page_obj содержит текущую часть. После показа верните 10.

## 23. Навигация по страницам

Покажите `templates/includes/pagination.html`: has_previous(), previous_page_number(), has_next(), next_page_number(). При PAGE_SIZE=1 сравните `?page=1` и `?page=2`. Невалидный page=abc даёт 400; положительный номер за пределами диапазона get_page() приводит к последней странице.

## 24. Сохранение фильтров в ссылках

При PAGE_SIZE=1 откройте `/questions/?sort=oldest`, нажмите «Далее». В адресе сохраняется sort и меняется page. Тег `{% querystring page=... %}` сохраняет остальные GET-параметры. При повторной отправке формы поле page не выводится, поэтому выборка начинается с первой страницы.

## 25. Фильтры, порядок и страницы вместе

На `/questions/` задайте категорию или статус, выберите порядок и перейдите на следующую страницу при достаточном количестве результатов. filtered_questions() применяется до question_rows() и Paginator. Пагинация ограничивает уже отфильтрованный и отсортированный QuerySet. Для короткой демонстрации временно уменьшите PAGE_SIZE до 1.

## 26. Объекты без связанных записей

Создайте тестовую категорию без вопросов и откройте статистику с minimum=0: количество равно 0. Используется Category.objects.annotate(Count("questions")), поэтому сохраняется внешнее соединение. Если начинать выборку с Question.objects.values("category"), пустые категории пропадут. После показа удалите тестовую категорию.

## 27. Исключение через exclude

В unanswered_questions() исключаются CLOSED и WITHDRAWN, затем выбираются questions без answers. В shell сравните `Question.objects.exclude(status=Question.Status.CLOSED)` и `.exclude(status__in=[Question.Status.CLOSED, Question.Status.WITHDRAWN])`. Второй вариант исключает оба состояния.

## 28. Ограничение выборки

`list(Question.objects.order_by("pk")[:1])` вернёт не больше одного вопроса; `[1:3]` пропускает первый и берёт следующие два. Это LIMIT/OFFSET на стороне БД. В проекте рабочее ограничение выполняет Paginator; отрицательные индексы QuerySet не поддерживает.

## 29. get и исключения

`Question.objects.get(pk=1)` возвращает один объект. Несуществующий PK вызывает Question.DoesNotExist. Неуникальное условие, совпавшее с несколькими строками, вызывает MultipleObjectsReturned. Для демонстрации этих случаев используйте try/except; во view отсутствие записи преобразует в 404 get_object_or_404().

## 30. ORM в представлении

Покажите цепочку `/questions/` → questions() → list_response() → filtered_questions()/question_rows() → шаблон. Затем в браузере измените q или category. ORM меняет состав контекста, шаблон отображает его. Веб-часть больше не читает sql/queries.sql; файлы ПР7 сохранены для предыдущего этапа.
